# Установка и быстрые команды — руководство для первого запуска

Версия пакета: **v0.4, шаг 2 (предварительная)**. Самостоятельная работа не требует Matreshka Agent.
Инструкции предназначены для локальных Codex CLI/IDE, Claude Code, Cursor Agent и Antigravity.
Локальная установка сама по себе не устанавливает навык в облачные сессии, контейнеры, WSL или удалённые рабочие машины.

## 1. Что подготовить

Нужен Python **3.11 или новее** и распакованный пакет Context Optimizer с файлом `install.py` в корне.
Сторонние Python-библиотеки не требуются. Установщик не скачивает программы и не запускает pip/npm.

Откройте папку пакета в терминале: в ней должны быть `install.py`, `README.md` и каталог `skills`.
Не путайте её с папкой вашего сайта или приложения. В командах ниже путь проекта задаётся отдельно.

**Windows / PowerShell:**

```powershell
py -3 --version
```

**macOS / Linux:**

```bash
python3 --version
```

Если команда не найдена или версия ниже 3.11, установите актуальный Python с https://www.python.org/downloads/.
В Windows включите доступ к Python из терминала при установке, затем откройте новое окно PowerShell.
Не нужно отключать защиту PowerShell или запускать терминал от администратора.

Пакет можно получить в ZIP из проверенного релиза/проверенной ветки. При использовании Git:

```bash
git clone --branch dev/context-optimizer-v0.4-standalone https://github.com/GeneralAi360/Matreshk-context-optimizer.git
cd Matreshk-context-optimizer
```

Это **рабочая ветка**, не обещание стабильного релиза. Перед установкой просмотрите изменения и результаты CI соответствующего commit.
`install.py` работает с локальными файлами и не проверяет автора загруженного архива. Контрольные суммы выявляют изменения, но не заменяют доверие к источнику.

## 2. Выберите приложение и область установки

Для первого знакомства используйте установку **в один проект** — `--scope project` (это значение по умолчанию).
Установка `--scope user` делает навык доступным в нескольких локальных проектах и добавляет его в общий каталог навыков.

| Приложение | Значение `--host` | В один проект | В профиль пользователя |
| --- | --- | --- | --- |
| Codex | `codex` | `.agents/skills/context-optimizer` | `~/.agents/skills/context-optimizer` |
| Claude Code | `claude` | `.claude/skills/context-optimizer` | `~/.claude/skills/context-optimizer` |
| Cursor | `cursor` | `.cursor/skills/context-optimizer` | `~/.cursor/skills/context-optimizer` |
| Antigravity Desktop / IDE | `antigravity` | `.agents/skills/context-optimizer` | `~/.gemini/config/skills/context-optimizer` |
| Antigravity CLI | `antigravity-cli` | `.agents/skills/context-optimizer` | `~/.gemini/antigravity-cli/skills/context-optimizer` |

`~` означает домашнюю папку текущего пользователя. В Windows это обычно `%USERPROFILE%`.

**Общий каталог:** Codex и Antigravity в проекте используют один `.agents/skills`. Повторно ставить одну и ту же копию не нужно; её удаление затронет оба приложения. Cursor также может видеть навыки из совместимых каталогов. Не устанавливайте одинаковый навык в несколько каталогов без необходимости: в меню могут появиться дубли.

## 3. Предпросмотр установки через терминал

В командах замените примерный путь на настоящий путь к своему проекту. Кавычки сохраняйте, особенно если в пути есть пробелы.

### Windows / PowerShell

Из папки скачанного пакета выполните **одну** подходящую строку:

```powershell
py -3 install.py install --host codex --project "C:\Projects\Мой проект"
py -3 install.py install --host claude --project "C:\Projects\Мой проект"
py -3 install.py install --host cursor --project "C:\Projects\Мой проект"
py -3 install.py install --host antigravity --project "C:\Projects\Мой проект"
```

### macOS / Linux

Также выберите **одну** строку:

```bash
python3 install.py install --host codex --project "/полный/путь/к/проекту"
python3 install.py install --host claude --project "/полный/путь/к/проекту"
python3 install.py install --host cursor --project "/полный/путь/к/проекту"
python3 install.py install --host antigravity --project "/полный/путь/к/проекту"
```

Для Antigravity CLI используйте `--host antigravity-cli`. Для профиля пользователя замените `--project ...` на `--scope user`.

Установщик пока **ничего не записывает**. Он показывает `target` — куда установит навык, количество файлов и `approval` — строку вида `INSTALL-...`.
Проверьте путь. Скопируйте значение `approval` целиком и повторите свою команду, добавив `--approve`.

Пример подтверждения в Windows:

```powershell
py -3 install.py install --host codex --project "C:\Projects\Мой проект" --approve "INSTALL-ВСТАВЬТЕ_ПОЛНУЮ_СТРОКУ"
```

В macOS / Linux:

```bash
python3 install.py install --host codex --project "/полный/путь/к/проекту" --approve "INSTALL-ВСТАВЬТЕ_ПОЛНУЮ_СТРОКУ"
```

`INSTALL-ВСТАВЬТЕ_ПОЛНУЮ_СТРОКУ` — обозначение, не рабочий токен. Используйте строку именно из вашего предпросмотра.
Если пакет, путь или установленные файлы изменились, старое подтверждение перестанёт действовать.

## 4. Проверка после установки

```powershell
py -3 install.py doctor --host codex --project "C:\Projects\Мой проект"
```

Или:

```bash
python3 install.py doctor --host codex --project "/полный/путь/к/проекту"
```

Подставьте свой `--host` и ту же область установки. `doctor` проверяет файлы и manifest, но не запускает интерфейс приложения.
После этого обновите список навыков или перезапустите приложение, открыв нужный проект.

## 5. Быстрые команды в чате, не в терминале

| Действие | Codex | Claude Code / Cursor / Antigravity |
| --- | --- | --- |
| Помощь | `$context-optimizer help` | `/context-optimizer help` |
| Проверка среды | `$context-optimizer doctor` | `/context-optimizer doctor` |
| Начало нового проекта | `$context-optimizer start` | `/context-optimizer start` |
| Первый аудит готового проекта | `$context-optimizer adopt` | `/context-optimizer adopt` |
| Продолжение в новом чате | `$context-optimizer resume` | `/context-optimizer resume` |
| Повторный аудит | `$context-optimizer check` | `/context-optimizer check` |
| Последний отчёт | `$context-optimizer status` | `/context-optimizer status` |
| Предложения оптимизации | `$context-optimizer optimize` | `/context-optimizer optimize` |
| Память проекта | `$context-optimizer remember` | `/context-optimizer remember` |
| Итог перед закрытием | `$context-optimizer finish` | `/context-optimizer finish` |

В Codex можно сначала ввести `/skills` и выбрать навык. В остальных приложениях начните с `/` и выберите `context-optimizer` из меню.
Вызов без режима показывает помощь, а не запускает дорогую проверку.
Это **наши режимы**, а не встроенные `/status`, `/resume` или `/context` редактора.

### Первый день работы

Откройте существующий проект. Вызовите `doctor`, затем `adopt`.
Агент должен показать отчёт на русском, найденные проблемы, ограничения измерений и путь сохранения.
Затем вызовите `optimize`, чтобы обсудить наиболее полезные изменения. Сам вызов **не разрешает** удалять инструкции, отключать MCP или менять настройки.

После принятия порядка работы вызовите `remember`. Агент покажет небольшой блок для файла инструкций и запросит подтверждение конкретного содержания.
В следующем чате используйте `status` для чтения сохранённого отчёта или `resume` для нового аудита.
Перед завершением текущей сессии выполните `finish`.

### Когда повторять аудит

После заметного роста инструкций, смены skills/MCP, повторных чтений одних файлов, частых сжатий истории или существенного изменения структуры проекта.
Не нужно выполнять `check` после каждого сообщения. Отсутствие нового сигнала — повод продолжить работу, а не запускать ещё один аудит.

## 6. Что сохраняется и какие есть ограничения

Явные быстрые команды start/adopt/resume/check/optimize/finish сохраняют отчёты в `.context-optimizer/` внутри проверяемого проекта.
Для аудита без записи укажите в запросе `--read-only`; обработчик передаст его автономному режиму.
`status` читает последнее состояние без нового аудита. `remember` пишет только после отдельного подтверждения MEMORY-...

HTML-отчёт можно открыть обычным браузером. Это локальный отчёт, не фоновый сервер и не запись в облако.
Состояние следующего чата — `.context-optimizer/STATE.md`. Принятые изменения и проверка эффективности — отдельные сущности.
Отчёты могут содержать приватные сведения: автоматическое скрытие общих шаблонов секретов не гарантирует удаления всех секретов.

**Не добавляйте в Git:** `.context-optimizer/` и `.context-optimizer-installer/`.
Установщик не правит `.gitignore` без запроса. Проверьте `git status` перед коммитом.
Сами файлы навыка можно коммитить отдельно после проверки; локальный manifest не является подписью автора.

**Cursor:** навык и статический аудит работают; собственный сбор runtime-счётчиков Cursor ещё не реализован. Чужая история Codex не выдаётся за данные Cursor.
**Другие приложения:** точные показатели возможны только при подходящих локальных журналах. Неполные данные обозначаются как неизвестные/частичные.
**finish:** запускается явно; автоматического hook на закрытие окна нет. Уменьшение байтов инструкций не доказывает экономию токенов или сохранение качества.
**Применение произвольных исправлений:** универсальный executor ещё проходит отдельное усиление. В данном шаге автоматическое изменение инструкций доступно только через ограниченный подтверждаемый `remember`.

## 7. Обновление

Скачайте новую проверенную версию в **другую** папку и откройте её терминалом. Остановите текущую работу агента на время замены файлов навыка.
Из нового пакета выполните предпросмотр:

```powershell
py -3 install.py update --host codex --project "C:\Projects\Мой проект"
```

```bash
python3 install.py update --host codex --project "/полный/путь/к/проекту"
```

После проверки повторите ту же команду с `--approve "INSTALL-..."` из нового предпросмотра. Запустите `doctor` и перезапустите приложение.
Старая копия сохраняется в `.context-optimizer-installer/backups/` выбранной области, вне каталогов skills.
Обновление не удаляет результаты аудитов и не изменяет `AGENTS.md`, `CLAUDE.md`, `GEMINI.md`, настройки или разрешения приложений.

При ручных правках внутри установленного навыка update остановится. Сохраните и разберите эти правки; кнопки «затереть всё» нет.
Не редактируйте manifest для обхода проверки. Сбои/прерванные операции фиксируются в `.context-optimizer-installer/transactions/`.
Если обнаружена незавершённая операция, сначала проверьте журнал и резервные копии; автоматического опасного отката нет.

## 8. Удаление

Используйте тот же пакет установщика, host и scope:

```powershell
py -3 install.py uninstall --host codex --project "C:\Projects\Мой проект"
```

```bash
python3 install.py uninstall --host codex --project "/полный/путь/к/проекту"
```

Проверьте предпросмотр и повторите с актуальным `--approve "INSTALL-..."`.
Навык убирается из активного каталога в резервную копию. Аудиты, память проекта и чужие навыки остаются.
Папки backups не загружаются как установленные skills. Удалить резервные копии окончательно можно вручную после проверки, не во время работы.
Если удаляете общую `.agents/skills/context-optimizer`, она перестанет быть доступна и Codex, и Antigravity в этом проекте.

## 9. Если команда не появилась

Проверьте `doctor`, открытый проект, выбранный scope и где фактически работает агент (Windows, WSL, SSH, контейнер, облако).
Пользовательская копия на Windows не появляется автоматически внутри WSL или на удалённом сервере.
Обновите список skills или перезапустите приложение. В Codex проверьте `/skills`; в Claude Code, Cursor и Antigravity — меню `/`.
При дублях оставьте одну осознанно выбранную установку. Не меняйте глобальные настройки и разрешения ради появления команды.
Если интерфейс старой версии не поддерживает данный формат, воспользуйтесь терминальным запуском из установленного каталога:

```text
python3 -B "<папка-навыка>/scripts/quick.py" --harness codex --project "<корень-проекта>" adopt
```

На Windows замените `python3` на `py -3`. Harness: `codex`, `claude`, `cursor`, `antigravity` (для Antigravity CLI тоже `antigravity`).
