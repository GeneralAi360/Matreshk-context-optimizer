# Автономная работа: первый шаг v0.4

Matreshka Agent не требуется. Пока это запуск из скачанного репозитория, не завершённый
установщик быстрых команд для четырёх приложений. Нужен Python 3.11 или новее.

## Первый запуск

Откройте терминал в каталоге репозитория навыка. Вместо `<проект>` подставьте полный путь
к своему проекту; путь с пробелами оставляйте в кавычках. В Windows используйте `py -3.11`
или установленный `python`, в macOS/Linux обычно `python3`.

```bash
python -B skills/context-optimizer/scripts/standalone.py --project "<проект>" --save adopt
```

Для нового проекта замените `adopt` на `start`. Для локальных счётчиков добавьте
`--provider codex` / `--provider claude` / `--provider antigravity`. Без этого флага
выполняется статический аудит и честно показывается отсутствие точной телеметрии.
Cursor можно использовать для работы с проектом и чтения отчётов; нативный parser его
токенов пока не реализован. Не выдавайте данные Codex на том же компьютере за расход Cursor.

Без `--save` команда ничего не сохраняет в проект. С `--save` создаются:

```text
.context-optimizer/
  audits/audit-<id>/audit.json
  audits/audit-<id>/report.md
  audits/audit-<id>/report.html
  latest.json
  baseline.json
  STATE.md
```

Откройте `report.md` в редакторе или `report.html` в браузере. Это полный локальный отчёт;
компактный bridge остаётся пригодным для интеграции с Matreshka. Снимки не перезаписываются.
Не добавляйте `.context-optimizer/` в Git: в отчётах могут остаться приватные сведения.
Файлы не отправляются в сеть. Скрытие распространённых ключей не заменяет проверку перед публикацией.

## Когда какая команда нужна

| Команда | Ситуация | Запись |
|---|---|---|
| start | Новый проект, нужен исходный снимок | Только с --save |
| adopt | Первое подключение к существующему проекту | Только с --save |
| resume | Новый чат или продолжение после паузы | Только с --save; не сбрасывает baseline |
| check | Есть признаки перегрузки или заметные изменения | Только с --save |
| status | Прочитать последний результат без повторного аудита | Не пишет; при отсутствии отчёта делает read-only аудит |
| optimize | Получить предложения, начиная с менее рискованных | Не применяет предложенные изменения |
| finish | Явно завершить сессию и сохранить сравнение | Только с --save |
| remember | Связать состояние с правилами следующего чата | Предпросмотр; запись только по точному --approve |

Порядок аргументов: сначала `--project`, `--provider`, `--save`, затем команда.
Не запускайте полный аудит после каждого сообщения. `status` значительно дешевле повторного `check`.

## Память следующего чата

Сначала сохраните аудит. Затем запросите предпросмотр:

```bash
python -B skills/context-optimizer/scripts/standalone.py --project "<проект>" --harness claude remember
```

Проверьте показанный блок. Для подтверждения повторите вызов, добавив **ровно** полученное
значение `approval` через `--approve "MEMORY-..."` перед `remember`. Не придумывайте этот токен.

Файлы: Codex/Cursor — `AGENTS.md`, Claude Code — `CLAUDE.md`, Antigravity — `GEMINI.md`.
Вставляется только ссылка на состояние и ограничения; исходные правила пользователя сохраняются.
Повторный запуск не размножает блок. Резервная копия и запись действия сохраняются в
`.context-optimizer/handoff-backups/`. Повреждённые маркеры, ссылки и изменение файла между
предпросмотром и подтверждением останавливают запись. Внешние организационные правила не изменяются.

Этот шаг сохраняет ссылку на состояние, а не объявляет все рекомендации принятыми.
Без отдельной проверки нельзя автоматически переносить произвольный текст логов в инструкции.

## Завершение

```bash
python -B skills/context-optimizer/scripts/standalone.py --project "<проект>" --provider codex --save finish
```

Сравниваются размеры инструкций с исходным снимком. Сессия помечается закрытой; следующий
`start`/`adopt --save` создаёт новый baseline. `resume` прежний baseline не сбрасывает.
Вывод «экономия токенов подтверждена» не делается по разнице байтов или накопительных счётчиков.
Для такого вывода нужны сопоставимые задачи, одинаковая семантика метрик и проверка качества.

Закрытие окна редактора само по себе эту команду не вызывает. Фоновые процессы и hooks этим
шагом не устанавливаются. Полная автоматизация завершающего события — отдельная проверяемая интеграция.

## Границы текущего шага

Автономный слой сохраняет отчёты, показывает рекомендации и умеет безопасно связывать их
с памятью. Он не отключает MCP, не удаляет навыки и не применяет произвольный patch автоматически.
Универсальный путь изменения проекта требует отдельного усиления executor и его сквозных тестов.
