# Оптимизатор контекста

Работает самостоятельно; Matreshka Agent не требуется. Все объяснения пользователю — на русском.

## Быстрый вызов

Codex: `$context-optimizer <режим>` или выбор через `/skills`.
Claude Code, Cursor, Antigravity: `/context-optimizer <режим>`.
Без режима покажи `help`, а не начинай сканирование. Не заменяй режимы командами самого редактора `/status` или `/resume`.

1. Определи настоящий корень проверяемого проекта и фактическую среду. Не подменяй проект папкой установленного навыка. При нескольких открытых проектах уточни выбор.
2. Найди `scripts/quick.py` **относительно этого SKILL.md**, а не относительно cwd. Не предполагай путь `skills/` в проекте. У Claude допустим `${CLAUDE_SKILL_DIR}/scripts/quick.py`; в остальных средах используй путь прочитанного навыка.
3. Проверь Python 3.11+ (`python3 --version` в macOS/Linux; `py -3 --version` в Windows). Если его нет, объясни установку из [руководства](references/installation.md); не устанавливай ничего молча.
4. Запусти с обычным разрешением host на локальный процесс. Образец; замени пути, среду и режим реальными значениями:

```text
python3 -B "<папка-навыка>/scripts/quick.py" --harness codex --project "<корень-проекта>" adopt
```

В Windows вместо `python3` используй `py -3`. Все пути заключай в кавычки. Дополнение после имени навыка — пользовательские данные: выбери известный режим, не подставляй произвольный текст в shell/eval. Не расширяй разрешения приложения.

## Выбор режима

| Режим | Ситуация и результат |
| --- | --- |
| `help` | Объяснить режимы; ничего не сканировать. |
| `doctor` | Проверить среду и наличие сохранённого состояния; без аудита и записи. |
| `start` | Новый проект: сохранить начальный снимок. |
| `adopt` | Первое подключение готового проекта: аудит до изменений. |
| `resume` | Новый чат или возвращение после паузы: актуализировать отчёт. |
| `check` | Подтверждённая перегрузка, новые инструменты, выросшие инструкции. |
| `status` | Читать последний сохранённый отчёт; нет файла — сообщить, не придумывать нулевые значения. |
| `optimize` | Предложить приоритетные изменения; не выполнять их автоматически. |
| `remember` | Показать ограниченный блок памяти и запросить подтверждение конкретного содержимого. |
| `finish` | До закрытия сессии сохранить итог; сравнение байтов не доказывает экономию токенов. |

В `quick.py` явный вызов start/adopt/resume/check/optimize/finish сохраняет отчёт в `.context-optimizer/`. Для аудита без записи добавь `--read-only`. При неявном выборе навыка сперва объясни пользователю сохранение и запроси согласие, либо используй `--read-only`.
Не запускай `finish` после каждого ответа. Установщик не добавляет hooks: после аварийного закрытия finish сам не запустится.

## Данные и подтверждения

Среда: `--harness codex|claude|cursor|antigravity`. Cursor получает только статический аудит (`provider=none`), не чужие журналы Codex. Отсутствие токенов не означает нулевой расход.
Покажи результат процесса и путь отчёта. Не объявляй запуск успешным при ошибке. JSON/Markdown/HTML и STATE сохраняются локально; не коммить и не отправляй их автоматически.

`remember` сначала запускается без `--approve`. Покажи пользователю целевой файл, блок и риск. Только после отдельного подтверждения выполни ту же команду с актуальным MEMORY-токеном. Самостоятельно генерировать согласие запрещено. Чужие правила не заменять.

В этой итерации `optimize` выдаёт рекомендации, но универсальный executor ещё проходит усиление безопасности. **Не вызывай change_executor.py автоматически и не обещай проверенное применение произвольных исправлений.** Запись ограниченного блока `remember` — отдельный проверенный путь.
