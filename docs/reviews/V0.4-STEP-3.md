# Ревью v0.4: шаг 3 — безопасное применение и quality verification

Дата: 24 сентября 2026.

## Усилено

- APPLY approval теперь content-bound: change JSON, resolved target, before SHA-256 и preview result.
- Legacy approval вида `CHG-001` больше не принимается.
- Строгая валидация change/finding IDs, params и validation fields.
- Запрещены mutation в `.git`, `.context-optimizer` и installer state.
- Project/user paths проверяются на symlink/junction; user-scope ограничен домашней папкой.
- Backup хэшируется сразу после копирования и повторно проверяется перед rollback.
- Target повторно проверяется после backup прямо перед mutation.
- Exact text replacement сохраняет исходные CRLF/LF.
- Фактический текстовый результат обязан совпасть с подтверждённым preview.
- Добавлен per-change lock; параллельный apply/rollback не выполняется молча.
- Rollback token привязан к стабильным полям journal; rollback не затирает post-apply user edits.
- Общий quality verifier используется и benchmark CLI, и change executor.
- `verify` различает `VERIFIED_KEEP`, `ROLLBACK_RECOMMENDED`, `NEEDS_MORE_DATA`.
- FAIL не выполняет rollback автоматически: для отката требуется отдельное подтверждение.

## Не обещается

- Автоматическая генерация безопасного change для любого finding. Агент должен сначала превратить рекомендацию в одну из трёх поддерживаемых операций и показать preview.
- PASS по static bytes. Без сопоставимых measured runtime/quality данных результат остаётся непроверенным.
- Защита от враждебного процесса того же OS-user между отдельными системными вызовами.
- Автоматический rollback без пользователя.

## Приёмка шага

Новые regression tests покрывают stale approval, изменившийся target, reserved paths, неизвестные params, повреждённый backup, post-apply edits, PASS/FAIL/UNVERIFIED quality verification и symlink target.
